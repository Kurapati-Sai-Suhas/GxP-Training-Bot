## 1 · Problem framing · 45s
**SCREEN** Window A, Dashboard.
**SAY** "Pharmaceutical staff must be retrained on SOPs. Today everyone gets the same quiz — so a
60% score tells you *who* struggled, not *what* with, and retraining repeats what they knew."

## 2 · SOP and chunking · 60s
**CLICK** **SOP Library** → point at `SOP-DEMO`, status **Processed**.
**SAY** "Three sections. Split by a three-tier cascade — heading detection first, semantic
chunking via embeddings if there are no headings, fixed-length as a floor. This one had numbered
headings, so tier one ran, and the strategy used is stored on every chunk."
**EXPECT** Processed, 3 chunks.
**BACKUP** If the list is empty, use the terminal demo (step 8) and narrate from its output.

## 3 · Generated questions · 45s
**CLICK** **Question Review**.
**SAY** "Nine questions, three per section, generated by Llama 3.1 8B on NVIDIA NIM. Each from a
single section, with a prompt that forbids outside knowledge."
**EXPECT** 9 cards with role, difficulty, confidence, NIM badges.

## 4 · Provenance ⭐ · 60s
**CLICK** "View source text" on any card. **Hold 8 seconds.**
**SAY** "This is how a reviewer answers 'where did this come from?' — the exact stored passage.
Being precise: this is provenance plus a prompt constraint. It is **not verified entailment**.
Nothing mechanically checks the answer follows from the passage. That's what the human is for."

## 5 · E-signature ⭐ · 60s
**SAY** "Approval requires the reviewer to re-enter their own password, checked server-side. The
system then stores a SHA-256 hash of the exact content approved — text, explanation, difficulty,
every option including which is correct. After that it's immutable: PATCH, PUT and DELETE all
return 403."
**BACKUP** If approval 400s: *"That's the control working — a wrong password changes nothing."*
Then re-type `demo12345`.

## 6 · The learner's position · 30s

**SAY** "The learner scored 33% — three of nine. A percentage tells a trainer who is struggling,
not what with. Watch what the system knows instead."

## 7 · Adaptive analysis ⭐⭐ **CENTREPIECE** · 2 min

**POINT AT** step [11]: `improved: 50.0% -> 100.0% (+50.0 points)` on both weak sections.
**SAY** "Fifty percentage points, computed from stored answers — oldest half against newest half.
Measured, not asserted. And this is a **verified controlled demonstration, not a user study**.

registering the improvement."

## 10 · Integrity ⭐ *(your differentiator)* · 60s
**SAY** "One thing I'd point out because it's recent work. The server now records exactly which
questions were offered for an attempt, and a submission must match that set precisely. Before
that, a modified client could answer only the questions it knew — two of six correct scored 100%,
because the score was computed over submitted answers. Now the denominator is the offered set, so
two correct and four unanswered of six is 33.33%. Partial, substituted and duplicated submissions
all return 400 with zero database writes."

## 11 · Audit and controls · 45s
**SAY** "Every action is attributed — 17 audit types. Controls: mandatory SME approval, signature
bound to a content hash, immutable approved content, RBAC, answer-key protection, server-side
validation. **GxP-oriented controls — I'm not claiming regulatory compliance.** Missing:
tamper-evident audit storage, separation of duties, a qualification record."

## 12 · Close · 30s
**SAY** "A closed adaptive loop: the SOP produced the questions, a qualified human signed them,
per-section performance identified the gaps, the system selected only the weak material, and the
improvement was measured. **AI generates the content. SMEs control it. Learner data drives
adaptation. FSRS controls timing.**"

## Failure recovery

| Symptom | Say | Do |
|---|---|---|
| Everything green, nothing recommended | "Let me reset to the starting state — 30 seconds." | `demo_adaptive --stop-after-analysis` |
| "0 available now" | "That's the reconciliation I described — the engine says weak, FSRS says not yet." | Use it; it's a feature |
| NIM slow/unreachable | "Fallen back to the deterministic offline generator — designed behaviour. Lower quality, not lower integrity." | Let it run |
| Backend down | "While that comes up — the management command runs the whole loop and prints every step." | Restart, narrate |
| Approval 400 | "That's the e-signature control working." | Re-type `demo12345` |
| 401s in console | "SPA fetches before the token restores. Cosmetic, pre-existing." | Don't open devtools |
| Asked something unknown | "I don't know that off the top of my head — let me tell you what I do know and where I'd look." | Never invent |
