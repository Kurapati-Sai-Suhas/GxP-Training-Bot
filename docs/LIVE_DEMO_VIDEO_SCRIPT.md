# THE SCRIPT

## PART 1 — Introduction · 0:00–0:40

**SHOW:** The application, logged in as `anjali` (admin), on the Dashboard.

**SAY:**
> "This is GxP Training Bot. In pharmaceutical manufacturing, operators must be trained and
> retrained on Standard Operating Procedures. Traditional SOP training generally provides the same
> material and the same assessment to every learner.
>
> This system uses AI to generate SOP-grounded questions, requires SME validation before anything
> reaches a learner, and then adapts subsequent training based on that learner's section-level
> performance. The adaptive loop is the focus of this demonstration."

## PART 2 — SOP ingestion and provenance · 0:40–1:30

**CLICK:** Sidebar → **SOP Library**.

**EXPECT:** `SOP-DEMO — Quality Management Essentials`, status **Processed**, 3 chunks.

**SAY:**
> "This is a controlled SOP with three sections: Good Manufacturing Practice, CAPA and Root Cause
> Analysis, and Documentation Practices.
>
> The document is processed into smaller sections, or chunks, so that generated questions maintain
> provenance back to the original SOP content. The system detected the numbered headings, so each
> chunk corresponds to a real section of the procedure rather than an arbitrary character cut. That
> chunk is the unit everything adaptive is built on."

## PART 3 — AI question generation · 1:30–2:30

**CLICK:** Sidebar → **Generate Quiz** *(visible on the admin account only)*.

**SHOW:** the SOP dropdown, job-role dropdown, difficulty and count controls.

**THEN CLICK:** Sidebar → **Question Review** to show the nine already-generated questions.

**EXPECT:** 9 cards with badges — role, difficulty, confidence, **NVIDIA NIM**, Elo rating.

**SAY:**
> "Nine questions, three per section, generated by Llama 3.1 8B running on NVIDIA NIM. Each was
> generated from a single chunk, with a prompt that supplies only that section's text and instructs
> the model not to use outside knowledge.
>
> The LLM generates the assessment content. The LLM does **not** decide learner adaptation — the
> adaptive engine independently uses learner performance data to determine what should be
> retrained."

> ⚠️ Do not open `.env`, terminal history containing keys, or devtools during this part.

---

## PART 4 — SME review and electronic signature · 2:30–3:30 ⭐

**CLICK:** on a question card → expand **"View source text"**.

**EXPECT:** the exact stored SOPChunk passage.

**SAY:**
> "This is how a reviewer answers 'where did this question come from?' The passage shown is the
> exact chunk the question was generated from.
>
> To be precise: this is provenance plus a prompt constraint. It is **not** verified entailment.
> Nothing mechanically checks that the correct answer follows from this passage — that is what the
> human gate is for."

**THEN:** log in as `demo_sme` (or show the approval control) and describe approval.

**SAY:**
> "AI-generated questions are not immediately exposed to learners. An SME reviews and approves them
> first, and approval requires the reviewer to re-enter their own password, verified server-side.
>
> On success the system stores a SHA-256 hash of the exact content approved — question text,
> explanation, difficulty, and every option including which one is correct. The electronic signature
> is bound to the approved content, which preserves the integrity of the approved assessment. After
> that the question is immutable: edit and delete both return 403."

## PART 6 — Adaptive analysis · 4:20–6:00 ⭐⭐ **THE CENTREPIECE**

**SHOW:** the section cards on My Learning Path. Read them top to bottom.

**POINT AT, in this order:**

| Element | Say |
|---|---|
| Sections 3 and 2, red, **Priority: HIGH** | "Two sections flagged weak" |
| `Adaptive score: 0%` | "This is the number the decision was made on" |
| `Lifetime: 0%` / `Recent: 0%` | "Both are shown, so the screen can never contradict its own verdict" |
| `Answered: 0/3` | "Three responses — enough evidence to act on" |

**SAY:**
> "The system does not simply retrain the entire SOP. It evaluates performance at section level.
>
> Good Manufacturing Practice is strong, so it is excluded. CAPA and Documentation Practices are
> weak, so both are selected at HIGH priority.
>
> On the classification: the priority layer is **rule-based over a recency-weighted statistical
> signal**. The system also contains two model-based components — **Elo** estimates learner ability
> and question difficulty online, and **FSRS** models memory and review timing. It is a hybrid
> adaptive system; it is not a single trained machine-learning model."

---

## PART 7 — Why the system is explainable · 6:00–7:00 ⭐

**SHOW:** the reason line under each section card.

**EXPECT:** e.g. *"0.0% accuracy (0/3 correct) — below the 60% weakness threshold."*

**SAY:**
> "This matters because the system is explainable. It doesn't just say 'study this section'. It
> states the evidence that produced the recommendation: the measured accuracy, the number of
> responses, and the threshold that fired.
>
> In a regulated training context, a recommendation has to survive being questioned. A threshold and
> a count can be checked by a human. A neural network's output cannot."

**NOW POINT AT the "Scheduled for" badge and the "0 available now" header.**

**SAY:**
> "And here is the part I'm most pleased with. These sections are flagged HIGH — the engine says
> they need work. But the badge says **scheduled for later**, and the header says **0 available
> now**.
>
> That is two different algorithms answering two different questions. Adaptive selection answers
> *what* needs attention. FSRS answers *when*. They are deliberately separated, because
> retrievability immediately after an assessment does not indicate which content the learner
> performed poorly on — mathematically, it returns 1.0 for every section at that moment.
>
> So the interface reports both, and never promises a quiz that doesn't exist."

# FAILURE RECOVERY

| Symptom | Cause | Fix | What to say |
|---|---|---|---|
| **Login fails** | Wrong password, or the 10/min login throttle tripped | Use `demo12345`; wait 60s if throttled | "That's the rate limiting on the login endpoint — it's a deliberate control." |
| **Every screen empty; console shows connection refused** | Backend not running | `cd backend && uv run python manage.py runserver 8000` | "While that starts — the management command shows the entire loop end to end, so I can demonstrate it without the UI if needed." |
| **NVIDIA NIM slow or unreachable** | Provider unavailable or rate-limited | None — let it fall back | "The provider is unreachable, so it has fallen back to the deterministic offline generator. That's designed behaviour: three retries with backoff, then a fallback whose correct answer is taken verbatim from the SOP text, so it cannot hallucinate. Questions are tagged so a reviewer can see which path produced them." |
| **Generation fails outright** | Provider error | Use the 9 questions already in Question Review | "The nine approved questions are already in the review queue — those were generated live earlier." |
| **No questions appear in review** | Wrong SOP or role filter | Select `SOP-DEMO` and the learner's job role | — |
| **SME approval rejected (400)** | Wrong password, or e-signature throttle (20/min) | Re-type `demo12345`; wait 60s | "That's the electronic-signature control working — a wrong password returns 400 and changes nothing." *(A good accidental demo — use it.)* |

```
Live demonstration of GxP Training Bot, an AI-assisted adaptive training and assessment
platform for pharmaceutical Standard Operating Procedures.

The system ingests a controlled SOP, splits it into sections, and uses an LLM (Llama 3.1 8B
via NVIDIA NIM) to draft assessment questions from one section at a time. Every question
requires SME approval under an electronic signature bound to a SHA-256 hash of the approved
content. Learner performance is then measured per SOP section and used to select the content
of subsequent training.

Adaptive engine (hybrid):
- Rule-based priority over a recency-weighted accuracy statistic (half-life 5 responses)
- Minimum-evidence gate before a section can be excluded
- Elo for online learner-ability and question-difficulty estimation
- FSRS (DSR memory model) for review scheduling

The LLM generates assessment content; it does not determine adaptive priority.

Verified controlled demonstration: the learner scores 33% on nine questions, receives six
targeted questions instead of nine with the already-mastered section excluded, and improves
from 50% to 100% on both weak sections. This is a controlled system demonstration, not a
statistical user study.

regulatory-compliant system.
```
